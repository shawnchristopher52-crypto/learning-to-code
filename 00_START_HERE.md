## What This Is

This is your **personal computer science curriculum** — a complete, structured program designed to take you from absolute beginner (Day 0) to genuinely proficient developer who can tackle complex projects independently.

By the end, you'll have:

- A working understanding of how computers and software actually function
- Fluency in two production languages (Python and JavaScript)
- Solid computer science fundamentals (data structures, algorithms, system design)
- A **portfolio of 8–10 real projects** on GitHub that demonstrate your skills
- The ability to learn any new framework, library, or language on your own

This is roughly equivalent to a strong undergraduate CS education, plus modern industry skills that universities often skip.

## How This Curriculum Is Organized

The journey is split into **6 phases**, each containing weekly modules:

| Phase | Focus | Estimated Duration |
|-------|-------|--------------------|
| **Phase 1: Foundations** | How computers work, environment setup, your first programs | ~4 weeks |
| **Phase 2: Python Mastery** | Become fluent in your first language | ~8 weeks |
| **Phase 3: CS Fundamentals** | Data structures, algorithms, problem-solving | ~8 weeks |
| **Phase 4: Web Frontend** | HTML, CSS, JavaScript, building interfaces | ~8 weeks |
| **Phase 5: Web Backend** | Databases, APIs, servers, deployment | ~8 weeks |
| **Phase 6: Modern Stack + AI** | React, full-stack apps, AI integration, capstone | ~12 weeks |

**Total: ~48 weeks at 6–10 hours/week.**

That said — this is *your* pace. If a week takes 10 days, that's fine. If you crush a week in 3 days, move on. The curriculum is the map; you set the speed.

## How Each Week Works

Every week's folder will contain:

1. **`README.md`** — The lesson itself. Read this first. Concepts, explanations, why things matter.
2. **`exercises/`** — Hands-on coding exercises. Don't skip these. Coding is a *skill*, not knowledge — you only learn by doing.
3. **`project/`** — A small applied project that uses what you learned that week.
4. **`solutions/`** (added after you complete the week) — Reference solutions to compare with yours.

### The Learning Loop

For each week, follow this loop:

1. **Read** the lesson (README.md)
2. **Try** the examples by typing them out yourself (don't copy-paste!)
3. **Do** the exercises — struggle is normal and good
4. **Build** the project — this is where understanding solidifies
5. **Reflect** — update `progress_log.md` with what you learned and what was tricky
6. **Commit** to GitHub — every week's work goes into your repository

When you're stuck, come back to this chat and ask me. I'll help you debug, explain things differently, or give hints (not always answers — productive struggle is part of learning).

## The Most Important Rule: TYPE EVERYTHING

When you see code in a lesson, **don't copy and paste it**. Type it out yourself, character by character.

This feels slow and tedious. It is. **It also works.** Your fingers learning the syntax is a real, physical part of learning to code. You'll catch errors, notice patterns, and build muscle memory you can't get any other way.

The only exception is when copying long blocks of boilerplate (like setup files). For everything else: **type it out.**

## How to Work With Me (Your Teacher)

I'm here whenever you need help. Here's how to get the most out of our sessions:

### When to come to me

- **Stuck on a concept** — "I read this lesson and don't understand X"
- **Stuck on code** — "Here's my code, here's the error, here's what I tried"
- **Ready for review** — "I finished the project, can you review it?"
- **Ready for the next week** — "I finished Week 2, please build Week 3"
- **Curious** — "Why does Python do this thing?" or "How does X work?"

### How to ask good questions

The faster you learn to ask precise technical questions, the faster you'll grow. A great question includes:

1. **What you were trying to do** ("I'm trying to make the function return a list of even numbers")
2. **What you actually saw** (paste the error or wrong output)
3. **What you've already tried** ("I tried changing the loop, but...")

This habit will serve you for your entire career. Bad questions waste everyone's time. Good ones get fast, useful answers.
